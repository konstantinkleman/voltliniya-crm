# Сверка калькулятора CRM с Excel

Нужен LibreOffice и файл `Калькулятор_ВольтЛиния.xlsx` (источник истины).

```
cd backend/tests/excel_check
cp ~/…/Калькулятор_ВольтЛиния.xlsx ../calc.xlsx      # путь в fill.py: SRC = '../calc.xlsx'
python3 gen_cases.py 200 23        # случайные замеры → cases.json
python3 fill.py                    # in/caseNNN.xlsx с этими данными
soffice --headless --calc --convert-to xlsx --outdir out in/*.xlsx   # пересчёт формул
PYTHONPATH=../.. python3 compare.py   # построчное сравнение + fixtures.json
```

`fixtures.json` из прогона кладётся в `backend/tests/calc_fixtures.json` — по нему CI проверяет движок без LibreOffice.
Корпус «накладной» в сверку не входит: в Excel (16.11.2026) формула подбора накладного корпуса берёт диапазон
со встраиваемыми корпусами и выбирает корпус больше нужного; в CRM — правильное правило из описания логики.

## Договор (пакет документов)

`app/contract.py` — перенос `сформировать_документы.py` (папка «Документы_ВольтЛиния_1» у владельца). Сверка 16.11.2026:
7 объектов (все тарифы, физлицо и ИП/ООО, материал заказчика, не учтённый материал, свой аванс) заполнены в Excel
вместе с листом «Договор», пересчитаны LibreOffice, пакет собран исходным скриптом и CRM; тексты договоров, актов,
памяток, квитанций и ячейки приложений совпали, кроме намеренных отличий:
- цена договора = сумма строк Приложения № 1 в напечатанном виде (кол-во и цена до копеек), до рубля — в Excel итог
  «СметаДанные» расходился со строками сметы на 1–3 ₽;
- в спецификации в разделе щита только аппараты и корпуса (скрипт добавлял туда «Оклейку окон» и «Вынос мусора»);
- e-mail заказчика-организации берётся из её реквизитов (скрипт брал e-mail физлица), подпись представителя — отдельным полем;
- «… один) рубль», «… два) рубля» вместо «рублей»; номер договора в нижнем колонтитуле договора и акта.
Без Excel пакет проверяет `tests/contract_test.py` (360 пакетов на фикстурах).
